# SAFE CLOUD — الإدارة الذكية وأمن الحوسبة السحابية

**منصة موحدة لإدارة وأمن الخوادم المحلية (`Offline`) والسحابية (`Online`)، وتقسيم الموارد، وتكامل الاستضافات وقواعد البيانات تحت ظل واحد — بإشراف الذكاء الاصطناعي وصمام الأمان البشري.**

> **المسابقة:** هاكاثون شراع 2026 للذكاء الاصطناعي العربي (`التحدّي المفتوح`)  
> **الفريق:** وحدة الظل السيبرانية (`Cyber Shadow Unit`)

## المشكلة والفجوة التي يعالجها النظام

تواجه المؤسسات الصغيرة والمتوسطة والمطورون ثلاث فجوات رئيسية في المنصات السحابية الحالية:
1. **فجوة المسؤولية المشتركة (`Shared Responsibility`):** تضمن الاستضافات بنيتها التحتية فقط، لكنها لا تتحمل مسؤولية أخطاء الإعدادات أو الصلاحيات المفرطة التي يرتكبها المستخدم.
2. **تشتت الأدوات وغياب المراقبة الشاملة:** تفتقر الاستضافات الخفيفة والمجانية إلى فحص أمني آلي متعدد الأدوات أو مراقبة تنبؤية مستمرة `24/7`، بينما تفرض السحابات الكبرى أدوات معقدة ومكلفة.
3. **محدودية الخطط المجانية:** تقيّد بعض المنصات لغات البرمجة أو قواعد البيانات، دون وجود طبقة موحدة تربط استضافات الأكواد بقواعد بيانات خارجية متغيرة لتعمل معاً كفريق واحد.

## المكونات والقدرات الرئيسية في النموذج الأولي (`MVP`)

### 1. الهوية، المصادقة، والصلاحيات (`RBAC`)
- لوحة تسجيل دخول وإنشاء حساب تدعم البريد الإلكتروني وخيارات **GitHub** و**Microsoft** و**Google** دون تخزين كلمات المرور في السجلات.
- تطبيق نظام الصلاحيات للأدوار الأربعة:
  - **مدير مؤسسة:** مخوّل بالاعتماد النهائي وتفويض صمام الأمان.
  - **مسؤول أمن:** فحص الإعدادات ورفع طلبات الإصلاح.
  - **محلل أمن:** مراقبة السجلات وتحليل الأحداث المشبوهة.
  - **مسؤول سحابة:** إدارة الموارد وتقسيم الخوادم والملفات.

### 2. استوديو إنشاء وإدارة السيرفر (`Server Studio & Control Panel`)
- **وضعان للإنشاء:** بيئة برمجة سحابية شبيهة بـ **VS Code** بأربع لوحات قابلة للطي مع فحص `Checkov + Trivy` قبل النشر، أو إعداد يدوي سريع يدعم **10 لغات برمجة** و**7 محركات قواعد بيانات**.
- **تقسيم الموارد:** إمكانية تقسيم الخادم الواحد إلى عدة خوادم (مثل `3` خوادم لخدمات مستقلة) مع تخصيص حصص `CPU / RAM`.
- **لوحة تحكم شاملة (9 تبويبات):** التشغيل/الإيقاف، الكونسول، إدارة الحزم والأعضاء ورسوم الاستهلاك، مدير الملفات، الإضافات (`FFmpeg, aria2, Tesseract`)، النسخ الاحتياطي، النشر (`Git / Docker / VS Code / ZIP`)، قواعد البيانات، مفاتيح `API / MCP`، ومتغيرات `.env`.

### 3. محرك الفحص الأمني الآلي والمؤشرات (`Multi-Scanner Engine`)
- استقبال وتوحيد مخرجات 5 أدوات فحص (`Checkov`, `Trivy`, `Prowler`, `ScoutSuite`, `Steampipe`) بصيغة `JSON Schema`.
- تطبيق **8 قواعد فحص ثابتة** مع اختبار ثلاثة سيناريوهات مدمجة: **عادي**، **حدّي**، و**فشل (`Fallback`)** حيث يتوقف التعديل التلقائي وتستمر القواعد الثابتة عند تعطل المكوّن الذكي.
- قياس **زمن الفحص بالمللي ثانية (`ms`)**، ودقة التصنيف، ونسبة التنبيهات الصحيحة والخاطئة، وإعادة التحقق التلقائي بعد الاعتماد.

### 4. دور الذكاء الاصطناعي، المراقبة 24/7، وصمام الأمان
- **ربط المؤشرات والسلوك:** يدمج المكوّن الذكي مخرجات الفحص مع سجلات الشبكة (`SSH / IDS / API`) ويرتب المخاطر (`P1 / P2 / P3`) مع توصيات إصلاح عملية.
- **المراقبة المستمرة والتنبؤ الاستباقي:** مراقبة لخادم محدد أو لجميع الخوادم بنبض دوري، وإصدار إنذار مبكر مع نسبة الخطر التنبؤية قبل وقوع الاختراق.
- **صمام الأمان الإلزامي (`Safety Valve`):** يحصر الوكلاء الذكيين افتراضياً في **المراقبة والتنبيه فقط**، ولا يسمح بتطبيق أي إعدادات وقائية إلا بتفويض صريح من **مدير المؤسسة** وتوثيق كامل في سجل التدقيق (`Audit Log`).

### 5. شبكة الاستضافات الخارجية وتكامل المنصات (`Multi-Cloud Mesh`)
- ربط استضافات الأكواد والواجهات (مثل `Vercel`, `Render`, `Pella.app`, `GitHub`) مع قواعد بيانات خارجية متغيرة (`PostgreSQL`, `Oracle`, `Turso`) لتعمل جميعها تحت ظل واحد.

| الفئة | المنصات المقارنة | الفرق الجوهري لصالح SAFE CLOUD |

## بنية الحزمة وخارطة النظام الإنتاجي

```text
safe-cloud-mvp/
├── index.html      # النموذج الأولي التفاعلي (SAFE CLOUD MVP)
├── report.html     # التقرير الشامل، العناصر السبعة لمنصة فلك، بوابة الفيديو، والمقارنة الموسّعة
├── vercel.json     # إعدادات التوجيه المباشر على Vercel
└── README.md       # التوثيق الكامل للمشروع والمنظومة
```

**خارطة التوسع الحقيقي (`Production Roadmap`):**
- **التثبيت المحلي المباشر (`Self-Hosted`):** حزمة تثبيت تعمل محلياً (`Offline`) على **Ubuntu / Linux** و**Windows Server**.
- **الربط السحابي الهجين (`Outbound Encrypted Agent`):** وكيل خفيف ينشئ نفقاً مشفراً صادراً (`mTLS / WireGuard`) لربط خوادم المؤسسة المحلية بالمنصة السحابية دون كشف المنافذ للإنترنت.
